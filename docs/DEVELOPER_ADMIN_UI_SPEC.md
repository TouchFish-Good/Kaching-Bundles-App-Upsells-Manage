# Developer Admin Console UI/UX 规格（阶段 3，待确认）

更新日期：2026-10-14。基于已确认的需求和独立管理服务方案。本文只定义界面行为，未实现页面或数据接口。

## 设计目标与依据

主要用户是需要反复搜索店铺、核查安装状态、追踪活动和错误的内部人员。界面应在三步内从异常总览到达某店铺的相关证据，并始终说明数据环境、时间及来源状态。视觉方向为“精密零售运营台”：延续商家端的 Ink、Sea、Coral 与 IBM Plex Sans/Noto Sans SC 字体，但采用更中性的工作区背景、更紧凑的表格和较少装饰。UI UX Pro Max 的 Data-Dense Dashboard 结果适用于信息密度、筛选和焦点要求；其 Enterprise Gateway 营销页面建议不适用于内部工具。React 栈表格搜索未返回有效条目，具体交互按现有项目约定及通用可访问表格原则定义。Frontend Design 的应用界面指导用于控制密度、排版、响应式和真实状态。

## 信息架构与导航

MVP 一级导航：Overview、Stores、Bundles、Errors；Owner 可见 Audit。P1 数据源验证后增加 Monitoring、Deployments。顶部常驻产品名、当前环境、数据更新时间、当前账号菜单；左侧固定导航承载模块。深链格式与技术 API 分开设计：`/overview`、`/stores`、`/stores/:storeId`、`/bundles`、`/stores/:storeId/bundles/:bundleId`、`/errors`、`/audit`。筛选、搜索、分页和时间范围编码在 URL 查询参数中，刷新和返回浏览器历史后保留上下文。无权模块不显示导航，但直接打开深链仍显示权限不足页并由服务端拒绝数据。

桌面宽度 >=1200px 使用 224px 侧栏和约 1280px 内容最大宽度；768–1199px 缩窄侧栏和工具栏；<768px 使用顶栏菜单、单列筛选和摘要式记录列表。活动与日志字段多时允许表格在 768px 左右水平滚动，关键标识列保持可见；移动端改为带清楚字段名的行摘要，不把所有列挤进窄屏。目标验证宽度：1440、1024、768、390、360px。主内容和导航不能相互覆盖。

## 页面结构

| 页面 | 顶部与主要内容 | 主要操作 |
| --- | --- | --- |
| Login / MFA | 品牌、账号输入、错误与恢复入口；MFA 步骤独立 | 登录、验证、使用恢复码；无公开注册 |
| Overview | 环境/时间范围；已安装店铺、有效活动、24h 错误指标；最近错误与数据源状态 | 指标跳至预筛选列表，错误跳至关联店铺 |
| Stores | 搜索/安装状态/环境筛选；商家表格、分页 | 打开详情、复制稳定 store ID |
| Store detail | 店铺身份、安装周期、授权 scope、活动摘要、最近错误 | 深入活动/错误，回到保留筛选的商家列表 |
| Bundles | 跨店活动搜索、店铺/状态/类型筛选、表格、分页 | 打开活动详情或店铺详情；业务只读 |
| Bundle detail | 店铺归属、活动状态、时间、档位与覆盖范围只读摘要、revision | 返回活动列表、跳转对应店铺 |
| Errors | 时间范围、环境、店铺、类型、严重度筛选；事件列表 | 打开脱敏事件详情、复制 trace ID |
| Audit | Owner 专用，操作人/动作/时间筛选与审计列表 | 查看记录详情；不提供编辑/删除 |
| Monitoring / Deployments（P1） | 健康及版本的可验证数据和观测时间 | 按环境、组件或时间过滤；无可信来源时不开放模块 |

核心页面的阅读顺序如下。Overview 先给环境、时间口径和来源状态，再列关键数字，最后列最近错误；用户可直接进入对应列表。Store detail 先确认店铺身份和安装状态，再看活动与错误。Errors 先给时间与过滤条件，再给可扫描事件行，详情在选中后展开。此顺序让排障人员始终知道“我在看哪家店、哪个环境、什么时间的数据”。

## Overview 指标和可视化

每个指标显示名称、值、口径简述、观测时间和来源状态。`null/unavailable` 显示“未接入”或“暂不可用”，绝不显示 `0`；`stale` 明示“数据延迟”及最后成功时间。错误数默认过去 24 小时，活动与店铺数是当前时点快照，时间语义不能混在同一标题下。MVP 不强制趋势图；P1 获得至少 4 个连续时间点后可用折线图展示安装/错误趋势，附可见数据表和直接标注，异常点除颜色外用形状/文字标记。少量数据优先用数字和列表。

## Stores 与 Bundles 列表

Stores 表格列：店铺名/handle、稳定 store ID、安装状态、当前安装时间、最近同步、活动数、最近错误、详情。默认按最近活动/更新时间倒序；具体排序以可用真实字段为准。搜索匹配稳定 ID、名称和域名，输入经短暂防抖后发起服务端查询，Enter 立即执行。状态筛选为 All/Installed/Uninstalled；未知状态单独标注。每次筛选变化重置游标；返回详情时恢复之前的 URL 状态。活动数无来源时显示短横线和解释，不显示零。

Bundles 表格列：活动名、店铺、类型、派生状态、计划时间、最后更新、详情。活动名重复时始终显示店铺身份。搜索活动名/ID，按店铺、状态、类型过滤；默认更新时间倒序。详情只读，无启停、删除或编辑按钮。活动数据源未接入时显示明确说明及最近检查时间；源正常但零记录时显示“暂无活动”；筛选后零匹配时显示“没有符合条件的活动”和清除筛选命令，三种状态不可混淆。

## Errors、Audit 与 P1 页面

Errors 表格列：发生时间、级别、事件类型、店铺、错误码、脱敏摘要、trace ID。默认最近 24 小时；允许受上限约束的自定义时间范围。点击行进入详情侧板，列出受控字段与来源，不展示原始 payload、token 或堆栈中的秘密。复制 trace ID 有短暂确认反馈。Audit 表格列：时间、管理员、动作、对象、环境、结果、request ID；按动作、管理员和时间过滤。P1 Monitoring 以服务探针、Webhook 处理与活动发布状态组织；每项显示最后观测时间，未观测为 Unknown。Deployments 区分“组件已发布”与“店铺已启用”，后者无可信数据时不展示为已启用。

## 状态与反馈

页面初载用与最终结构一致的骨架占位；筛选期间保留旧数据并标明正在更新，避免表格跳动。空状态按“真实零条、筛选零匹配、未接入、无权限、数据源故障”分别处理。接口 401 导向登录并保留安全的返回路径；403 显示权限不足与返回入口；404 显示对象不存在或不可访问；503 保留页面结构、显示来源故障和重试命令。部分 Overview 指标失败时只影响对应指标。错误提示使用可见文本与 `role=alert`，不会只靠颜色或 toast。业务只读页面不出现不可用写按钮。

## 视觉令牌

沿用商家端识别色：Ink `#102A2A`（正文/导航）、Sea `#0F766E`（主交互）、Coral `#C6492D`（错误）、Amber `#A16207`（告警）、白色表面。工作区改用中性 `#F5F7F7`，边线 `#D9E0DC`，次要文字 `#52615D`；成功淡底 `#DDF6EF`。这些令牌是 UI 草案，实施前需实测文本与状态对比度达到 WCAG 2.2 AA。字体用现有 IBM Plex Sans/Noto Sans SC，标识和 trace ID 使用等宽回退；正文 14px/20px，表格 13–14px，页面标题 24px/30px，面板标题 16px/22px。间距以 4px 为基础，表格行目标高度 44–48px，控件至少 40px，触屏关键目标至少 44px。控件圆角 6px，框架表面不超过 8px；页面区块用边线而非浮动卡片组织。焦点环清晰可见，状态同时使用文字和色彩；不使用装饰性 Banner。

## 表单、弹窗与响应式

登录表单用明确 label、`autocomplete=username/current-password`，允许密码管理器和粘贴；失败信息不透露账号是否存在。MFA 支持粘贴一次性验证码，并提供恢复码途径；若最终选 WebAuthn，保留可访问回退流程。输入错误显示字段旁说明，提交失败聚焦可访问错误摘要。Owner 邀请/停用管理员的表单和确认弹窗在阶段 4 的权限管理工作中细化；停用明确对象与影响，并需重新验证当前 Owner 不会停用最后一个 Owner。详情内容长时使用可关闭的侧板或独立页面，不用套卡片。移动端侧板改全屏且返回焦点到触发控件。所有对话框可 Esc 关闭（不可中断的提交状态除外），焦点被限制在对话框内。

## 验收依据

后续实现需在桌面和移动端核对导航、搜索/筛选/分页、深链恢复、数据源故障、权限不足和审计访问；用真实接口确认所有数值。检查键盘焦点、名称、错误公告、缩放至 200% 的布局、360px 最小宽度与无重叠；颜色对比度、加载位移及移动列表扫描顺序须实测。静态原型仅可用于审阅设计，不能作为功能验收。
