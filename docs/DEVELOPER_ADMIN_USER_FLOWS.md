# Developer Admin Console 用户流程（阶段 3，待确认）

更新日期：2026-10-14。流程描述 UI 行为与状态，不表示 API 已实现。

## 1. 登录与 MFA

1. 管理员打开后台深链；未登录则进入登录页，后台保存同源、安全的目标路径。
2. 输入邮箱/密码并提交；校验失败在表单内显示统一错误，不透露账号是否存在，允许密码管理器和粘贴。
3. 密码通过后进入 MFA；验证成功轮换会话并进入原目标页。验证失败保留输入焦点与明确错误，次数受服务端限制。
4. 会话过期或账号停用时跳转登录并显示会话状态；登录后仅回到仍有权限的目标页，否则显示权限不足。

恢复码和 WebAuthn/TOTP 的具体分支依最终身份实现确定，但均需有键盘可完成的路径。首次 Owner 的离线 bootstrap 不在公开 UI 中出现。

## 2. 从异常到商家与活动

1. Operator 进入 Overview，选择环境并看到最近 24 小时错误数、观测时间和来源状态。
2. 点击错误数，打开已带环境和时间范围的 Errors 列表；按类型/严重度进一步筛选。
3. 打开事件详情侧板，读取脱敏摘要、错误码、trace ID 和关联店铺；复制 trace ID 可获得成功反馈。
4. 点击店铺进入详情，核查安装周期、授权 scope 和最近活动；进入关联活动详情查看只读配置摘要。
5. 返回时保留 Errors 筛选与滚动位置。事件无 store ID 时显示“无法关联店铺”，不猜测归属。

若错误数据源 unavailable，Overview 指标显示不可用及最后成功时间；Errors 显示重试和来源说明，不把 503 当作“零错误”。

## 3. 搜索商家并核查安装

1. Viewer 在 Stores 输入店铺名、域名或稳定 ID，按 Enter 查询；状态可筛 Installed/Uninstalled。
2. 结果表显示环境和匹配商家，用户通过稳定 ID 确认目标；重名或改域名仍可辨认。
3. 进入详情查看当前状态、历史安装周期和更新时间，再按需要跳转该店活动。
4. 返回商家列表时恢复搜索、状态及分页。筛选无匹配提供清除筛选；真实无商家与未接入分别说明。

重装店铺在历史中显示不同安装周期，但列表和 Overview 当前安装店铺数按稳定 ID 去重。卸载记录可见范围和保留期按最终政策决定。

## 4. 跨店活动查询

1. Viewer 从 Bundles 选择环境、店铺、类型和状态，输入活动名或 ID，服务端返回分页列表。
2. 每一行同时显示活动与店铺身份，避免同名活动混淆；点击活动进入详情。
3. 详情显示派生状态、计划时间、档位和覆盖范围的只读摘要、revision 与最后更新时间。
4. 若真实活动持久化未接入，列表显示“活动数据源未接入”；若已接入但无活动，显示“暂无活动”。用户无法在后台启停或编辑活动。

对象已删除或不属于路径中的店铺时显示 404，不能泄露其他店铺活动的存在性。

## 5. 审计与权限

Owner 从 Audit 按管理员、动作和时间过滤，查看登录、敏感详情访问与管理动作。Operator/Viewer 不见 Audit 导航；直接打开深链显示权限不足，API 返回 403。Owner 停用账号时，确认弹窗说明所有会话将失效；服务端拒绝停用最后一个 Owner。审计写入失败时停用操作失败，页面保留错误供重试。

## 6. P1 监控与部署

已接入可信指标后，Operator 可从 Monitoring 查看服务探针、Webhook 和发布状态，逐项读出最后观测时间；无观测结果标 Unknown。Deployments 以环境和组件过滤版本记录，点击记录查看来源证据。部署记录不被表述为商家主题启用证明。数据源未验证前这两个模块不作为已上线流程。

## 7. 通用异常路径

401：引导重新登录；403：显示权限不足；404：显示对象不存在或不可访问；503：保留当前过滤条件，显示数据源故障与重试；部分指标失败：仅对应指标显示不可用。筛选请求取消或晚于新请求返回时，不覆盖当前结果。用户切换环境后清空与旧环境关联的 store ID、活动 ID 和分页游标，并在导航与页面标题处明确新环境。
