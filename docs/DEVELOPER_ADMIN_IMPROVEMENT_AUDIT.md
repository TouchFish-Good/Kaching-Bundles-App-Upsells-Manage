# 开发者管理后台完善清单

更新日期：2026-10-15。依据当前管理后台、商家应用代码及本地测试；真实 SHOPLINE 店铺和生产部署尚未验证。

## 本轮已改进

| 项目 | 结果 |
| --- | --- |
| 内部数据边界 | 管理 API 只投影 Overview、Stores、错误事件所需字段；异常结构和未定义响应返回数据源不可用。 |
| 敏感读取审计 | 按真实响应记录 `success`、`not_found` 或 `failure`；审计写入失败时不返回数据。 |
| MFA 尝试限制 | 待验证会话最多尝试 10 次；旧 SQLite 表启动时增加计数列。 |
| 本地监听 | 管理 API 默认只绑定 `127.0.0.1`，对外部署必须明确设置 `ADMIN_HOST`。 |

## P0：完成可信数据链路

1. **活动来源。** 商家页面仍使用原型活动数据，已有草稿仓库按 handle 存储。先让商家端页面读写真实仓库，再建立稳定 store ID 与活动的持久关联；管理端只读 API 才能开放列表、详情和有效活动计数。验收时必须用同一活动核对商家端与管理端，并测试跨店 ID 篡改返回 404。当前 Bundles 显示“未接入”是正确状态。
2. **真实店铺联调。** 在测试店验证 `v20260601` 店铺查询、授权/卸载/重装 Webhook、重复与乱序事件。当前安装清单仅经过本地夹具验证，不能代表 SHOPLINE 实测。
3. **折扣发布状态。** 商家 API 仍拒绝 active/scheduled 活动；Product Discount Function ID、GraphQL 发布/更新/删除、失败恢复和平台实际状态须联调后，才能展示“已发布”或把活动计入有效数。

## P0：生产运行边界

1. **持久化和恢复。** 管理账号、会话、审计及商家登记当前使用本地 SQLite；生产前确定托管数据库或单实例约束，完成备份、恢复演练与迁移方案。
2. **独立环境与网络。** 配置 HTTPS 反向代理、Secure Cookie、独立环境密钥和私网内部读取；多实例时将 HMAC nonce 重放记录迁至共享存储。`ADMIN_HOST` 仅在可信代理环境中设置为对外监听。
3. **管理员恢复。** 当前只有一次性 Owner 引导、邀请、停用与 TOTP；需定义 MFA 丢失、密码重置、紧急访问及密钥轮换流程。现有登录限速保存在进程内，生产多实例需共享限速存储。

## P1：可观测性与使用效率

1. 规定错误事件和审计的保留期限、清理策略、访问权限与必要的导出审计；验证失败事件的 store ID 和 trace ID 覆盖率。
2. 为服务健康、Function/Theme Extension 部署状态和历史趋势接入可信指标来源；没有采集数据时保持 unknown/unavailable。
3. 在真实活动源接入后补全 Bundles 搜索、筛选、分页、详情和商家详情中的活动摘要；对可见范围和移动端操作做浏览器验收。
